# Documents

Whatever outlives the turn. Terse, plain, short.

A document says what is true now. Git holds the history.

LLMs have a strong additive bias (Adams). Two effects: they append and patch where a rework was due, and they record every decision with its rejected alternatives. Fight both at every edit.

State goes in the shortest-lived store that outlives it: the conversation a turn, the notebook the session, the work file the work, the repo what the work leaves behind. Uncommitted is still conversation.

- Rework before adding: reread the section, rewrite it to hold the new; add a line only when no rewrite can.
- A document holds the state a decision produced. The decision, its reason and what lost go in the commit message.
- Written for a reader who never saw the version before: « now », « instead of », « no longer » are history, cut them.
- A work file is a backlog: a done line is rewritten to what is left, the file is deleted when the work ends. What crosses between sessions belongs to the `ongoing-work` and `handover` skills.
- Only logs append.
- The notebook holds the session: steps left, concerns, parked ideas. `grab-notebook` prints its path. Nothing outside the session names it.
- Read by a human: a figure of the whole on top, headings that tell the file alone, the text under them for the agent.
- For an agent, the field's own term: "bounded context", not "module".
- What is dropped is deleted, never prohibited. A behavior the model goes to unprompted is named by its pejorative ("primitive obsession").
