# 4E cognition

**Thesis.** The harness is built around human cognition, read as 4E (Newen, De Bruin & Gallagher): extended, embedded, enacted, embodied. Each face names what the engineer must keep to go on thinking when an agent does the work.

The same four faces read two humans: the engineer in the harness, the subject of this file, and the user in the software (φux).

| Face | Thinking needs | So the engineer keeps |
|---|---|---|
| Extended | a fast coupling | short turns, one conversation, a mind unloaded into files |
| Embedded | to be in what it thinks about | the domain code under their eyes |
| Enacted | to act with an intention | the solution: theirs, or understood and driven by them |
| Embodied | space | figures, and a codebase moved through |

## Extended

The agent and the files coupled to the act are part of the mind (Clark & Chalmers), and the coupling holds only while feedback is fast. Fast feedback drove TDD; with an agent it drives the shortest possible turn, and one conversation held rather than several agents multitasked.

Extending is also unloading, cognitive offloading (Risko & Gilbert): what the engineer holds in mind is written to a file, so it stops being held. What is unloaded is the holding, never the thinking.

## Embedded

Thinking happens in what is seen and what is around. An engineer immersed in the IDE, in flow (Csikszentmihalyi), thinks the code from inside it; moving away from the code risks losing this face. It matters most for the model (DDD): the engineer stays embedded in the domain code, the high-abstraction code first, to keep thinking the model and keep metis at work (φmetis-kairos, φcontinuous-design).

## Enacted

A problem is thought, and kept in mind, only by acting on it with an intention. Handing the agent a problem and taking back its solution breaks that: the engineer is out of the loop (Endsley), reviews a design they never built and holds no theory of it (Naur). So the agent applies a solution that comes from the engineer, as the strong-style driver applies the navigator's (φcollaborative-production); it does not invent one and apply it. This is where spec-driven development fails (φcontinuous-design).

The agent may help design the solution. Wherever the engineer must hold the result, the core domain (Evans), the model, the high-level code, the engineer still understands it and drives it into the code.

An agent that goes no further than what was asked is also how friction is noticed. Let loose, it takes the friction away, and with it the feel of model tension (φtransmission-belt, φmodel-phenomenology).

## Embodied

Thinking runs on the body's spatial machinery (Lakoff & Johnson): code, modules and models are held as places, and the engineer chooses how to move between them (φembodied-navigation). So wherever a human reads, a figure comes before prose (φconversation-as-interface).
