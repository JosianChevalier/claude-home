# Rationale: The Transmission Belt

The agent is a transmission between the engineer's type and the code's concept ([[philosophy/type-and-concept]]). This document says what kind of transmission, and what follows for a session.

## Belt, not gear

A belt differs from a gear in one property: **compliance**. It transmits torque but can slip, and the slip is a design property — it is what saves the engine when the load spikes, where a gear would pass the shock straight through. Read as a design principle, the belt already contains "make the friction felt": the belt is the part of the mesh where load becomes *perceptible to the engineer* instead of shearing something silently.

Two failure directions:

- **Too tight** — the harness absorbs the tension. The agent sporks — the veteran at scale ([[philosophy/type-and-concept]]) — and reports success.
- **Too loose** — nothing reaches the code. Intention is discussed and never crystallised.

## The return path

A belt runs both ways. The concept's **Enttäuschung** — Husserl's *disappointment*, the anticipation that the thing fails to fulfil — has to travel back up to the type, or the transmission has no return path. Without it you get the veteran's condition mechanised: a type that revises while the code does not.

Sweller's three loads are the constraint. Extraneous load is the medium's, and should go. Intrinsic load is the domain's, and cannot go. **Germane** load is the effort that builds the schema — it is *where the type grows*, through disappointment against a concrete concept. If the transmission is frictionless in that direction too, the engineer's type stops growing, and the agent becomes the only thing in the mesh that changes.

"Simplify the trivial, make the friction felt" is the Sweller split stated as a design principle. Its corollary is uncomfortable: the harness decides what counts as trivial, so the harness carries a concept of its own, and it can spork in its turn by classifying a real tension as medium. The test that keeps the classification in the open lives in [[philosophy/collaborative-production]].

## What the return path is for: destruction

Disappointment is not enough on its own. Boyd's *Destruction and Creation* supplies the active half. Any closed conceptual system's mismatch with reality grows on its own (his grounding: Gödel, Heisenberg, the second law), so destruction must be continuous and deliberate — destructive deduction shatters the existing domain, creative induction reassembles the parts into a new concept. This is the *Orient* step of the OODA loop: the capacity to **destroy a mental world**. Merleau-Ponty's deviation from maximal grip is passive: the world disappoints you. Boyd makes it a skill: the expert destroys their own gestalt before entropy forces the issue. In Husserl's terms, the epoché turned on oneself — bracketing the natural attitude is a controlled destruction of a world.

The full dynamic: tension (felt loss of Prägnanz) → destruction (Boyd, or voluntary disappointment) → **Stiftung** (the founding act after which the new figure is seen and the old one becomes hard to imagine). The moment someone says "this is a *Transfer*", six scattered fields snap into an object. Model Mitosis is a Stiftung event.

The return path exists to keep this dynamic on the engineer's side. What comes back up the belt is what the engineer destroys and refounds with. An agent that absorbs the disappointment removes the material of the engineer's Orient step.

## The harness, not the agent

The harness is not the agent's intelligence. It is the entire development process, and friction-feel is a property of that process — an emergent constraint in Juarrero's sense, set by the mesh, carried by no single part. Two axes of design follow:

- **Base layer: transparency.** The engineer stays situated in the code through direct feedback on change — highlighted diffs, diagrams, the implications of a change shown as it is made. This is the channel through which metis perceives; remove the showing and you have the recruit's condition at the speed of an agent. How to show is cartography ([[philosophy/zoom-levels]]); *why* it must be shown is this document.
- **Second axis: kairos.** Gates where the agent's sedimented culture supplies a second reading before the belt moves again: [[philosophy/kairos-gates]].

## What follows for a session

None of this is a rule; it is what a rule would be for.

- **The conversation is where the belt runs.** The type is predicated into a concept *in the exchange*; the artifact records the current state of that predication ([[philosophy/collaborative-production]]). The engineer's intention is carried, not improved: a better idea from the library is a second reading offered at a gate, never a substitution made in the code.
- **Translation is located, not diffused.** Diffusion — the spork ([[philosophy/model-expressions]]) — is the one failure the belt image predicts most directly, because the agent's fluency makes it cheap to produce and invisible to the producer.
- **When the type is silent, the choice returns up the belt.** If the engineer has not chosen among rival concepts, the choice is not made below.
- **Scale of change is a load signal.** Compliance is what lets a load spike register instead of transmit: a large, multi-concern change is where slip should show, as visible implication rather than accomplished fact.
- **Everything shown is shown so that metis can work on it.** Cartography ([[philosophy/zoom-levels]]), attention budget ([[philosophy/context-economics]]), and attractors ([[philosophy/attractors]]) govern *how*; the belt governs *why*.
